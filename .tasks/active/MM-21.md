# [MM-21] 출력 형식을 코드가 소유하도록 분리 (DQ·구도 프롬프트)

## 상태
진행 중 (1~4단계·charImage 양식 복구·캐릭터명 표기 보정 완료, 선택 항목 남음)

## 우선순위
🔴 긴급 (자동 모드 DQ 생성 JSON 파싱 오류 / 저장 템플릿에서 챕터 DQ 빈칸 소실 재발)

## 카테고리
Manual Mode / Auto Mode

## 증상
- 자동 모드 ①에서 `=== 1. [Th…` 는 유효한 JSON이 아니라는 오류. 저장된 DQ 템플릿의
  "=== / 코드블럭" 지시와 route가 덧붙이는 "JSON 배열로만 답하라" 지시가 충돌.
- 저장된 구도 템플릿에서 `{{questionItems}}`, `{{characterNote}}`가 사라져 어떤 챕터를
  골라도 DQ가 프롬프트에 조립되지 않음 (MM-20 재발, 다른 경로).
- 자동 모드 장면 분리가 3구간을 가정해서, 실제 4구간(제목/Problem/A/B) 데이터에서
  main 장면이 제목뿐이고 Option B 장면이 누락.

## 원인
출력 형식 지침이 사용자가 편집·저장하는 템플릿 안에 섞여 있었고, "템플릿으로 저장"이
화면 글을 역추적해 자리표시자를 복원하는 방식이라 편집 중 자리표시자가 소실될 수 있음.

## 조치 (완료: 1·2단계)
1. 템플릿은 내용 지침만, 출력 형식은 코드 소유로 분리
   - `lib/prompts.ts`: 기본 dq/composition 템플릿에서 형식 지침·예시 제거,
     Manual Mode용 `*_OUTPUT_FORMAT_INSTRUCTION` 추가 (프롬프트 끝에 자동 첨부, 편집·저장 대상 아님)
   - `lib/output-format.ts`: 형식 안내와 짝인 파서(`splitQuestionBlocks`, `splitCompositionScenes`)
   - `PromptBox`의 `appendix`로 복사 시 형식 안내 자동 첨부
2. 자동 모드는 Gemini 응답 스키마로 구조 강제 (`responseJsonSchema`), 앱이 Manual과 같은
   문자열 모양으로 조립해 저장. 등장인물은 등록된 캐릭터 목록으로만 제한(enum).
3. 저장된 템플릿에 필수 자리표시자(dq: selectedSummary, composition: questionItems)가
   없으면 기본 템플릿으로 대체하고 화면에 경고 (`resolvePromptTemplate`).
