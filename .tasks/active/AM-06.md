# [AM-06] 자동 모드 전체 파이프라인 서버 백그라운드 실행

## 상태
진행 중 (구현·로직 검증 완료, 실사용 확인 대기)

## 카테고리
Auto Mode

## 배경
배포된 dev에서 자동 모드를 돌리자 첫 단계에서 `TypeError: Failed to fetch`가 났다. AM-05는 장면 이미지
1장 단위만 서버 백그라운드로 옮겼고, 첫 단계(질문 → 구도 프롬프트)는 여전히 "브라우저가 요청 하나를
붙들고 서버가 끝날 때까지 기다리는" 구조였다. 그 요청 하나가 Gemini를 1 + 질문 수만큼 순서대로 부르므로
길어지고, 그동안 연결이 끊기면(탭 전환·절전·네트워크·서버 시간 제한) 서버가 에러를 돌려줄 기회도 없이
브라우저에는 "Failed to fetch"만 보인다.
- 원인은 서버 로그를 확인하지 못해 **미확정**. 요청이 길다는 구조적 문제는 코드로 확인했고, 이 티켓은
  그 구조를 없애는 것이 목적.

## 결정
- 자동 모드 전체(질문 → 구도 → 장면 이미지 전부)를 서버가 `after()`로 응답 이후에 끝까지 진행. 브라우저는
  "접수됐다"는 응답까지만 기다린다.
- 진행 상태를 브라우저 메모리가 아니라 챕터 문서의 **실행 기록**(`autoRun`)에 저장하고, 화면은 기존
  Firestore 실시간 구독으로 그것을 읽는다. 새로고침·재접속해도 같은 진행이 보인다.
- 실행마다 새 ID를 발급해서, 중지되거나 새 실행으로 교체된 실행이 뒤늦게 결과를 쓰지 못하게 한다.
- 이미지는 동시에 3장까지만 생성(요청 한도·서버 메모리 보호).
- 서버 함수가 시간 제한으로 끊기면 실행 기록이 "진행 중"으로 남으므로, 6분 넘게 갱신이 없으면 화면이
  "끊김"으로 판단해 다시 시작할 수 있게 한다. 이때 이미 만든 이미지는 남기고 빠진 것만 **이어서 생성**할 수 있다.
- 스타일 참고 이미지는 아직 브라우저 메모리에만 있으므로(AM-04 남은 작업), 실행을 시작할 때 한 번 서버로
  보낸다. 그래서 **실행 도중에 참고 이미지를 바꿔도 그 실행에는 반영되지 않는다**(AM-04의 "이후 장면부터
  반영"은 더 이상 사실이 아님).

## 구현
- `app/api/auto-run/route.ts` 신설: 검증 후 실행 기록을 남기고(이미 진행 중이면 409) `after()`로 파이프라인을
  넘긴 뒤 즉시 응답. `maxDuration = 300`.
- `lib/auto-run-pipeline.ts` 신설: 질문·구도 생성 → 저장 → 이미지 생성(동시 3장) → 종료 기록. 이미지 한 장을
  시작하기 전마다 실행이 아직 현재 실행인지 확인. 어떤 실패도 던지지 않고 실행 기록에 남김. `images-only`
  모드는 저장된 질문은 그대로 두고 이미지가 없는 장면만 생성.
- `lib/dq-generation.ts` 신설: 기존 `generate-dq` 라우트의 질문·구도 생성 로직을 그대로 이전.
  `app/api/generate-dq/route.ts` 삭제(호출하는 곳은 자동 모드 화면뿐이었음).
- `lib/auto-run.ts` 신설: 화면·서버가 함께 쓰는 판정(진행 중/끊김/현재 실행)과 장면 작업 목록 계산.
- `lib/firestore.ts`: 챕터 단위 갱신을 트랜잭션으로 묶는 `updatePart` 추가, 실행 시작/질문 저장/종료/중지
  함수 추가. 장면 결과 저장(`saveSceneImage`/`saveSceneImageError`)도 이 방식으로 교체(아래 "AM-05에서 발견한
  문제" 참고).
- `lib/scene-generation.ts`: 장면 한 장 생성·업로드를 `generateSceneImageUrl`로 묶어 개별 재생성 라우트와
  파이프라인이 공유. `lib/prompts.ts`: 화면·서버가 공유하는 `pickMentionedCharacters` 추가.
- `types/index.ts`: `NovelPart.autoRun`, `AutoRun`, `AutoRunMode` 등 추가.
- `lib/store.ts`: `stopAutoRun` 추가, 수동 모드가 질문 목록을 교체할 때 옛 실행 기록을 비움, 실행 기록은
  로컬 캐시에 저장하지 않음.
- `components/WorkPanel.tsx`: 로컬 진행 상태·루프 제거. 저장된 실행 기록에서 진행 목록·카드 로딩을 그림.
  "중지", "빠진 이미지 이어서 생성" 버튼 추가. 실행 중에는 개별 재생성 잠금. 요청 크기 초과(413) 안내.

## AM-05에서 발견한 문제
AM-05의 장면 결과 저장은 `parts.0.discussionQuestions.1.sceneImages.main`처럼 배열 순번이 든 경로로 문서의 한 필드만
갱신했다. Firestore SDK 소스(`ObjectValue.getFieldsMap`)에 "부모가 map이 아니면 새 map으로 바꾼다"고 명시돼 있어서,
`parts`가 배열이면 그 배열이 통째로 map으로 바뀌어 챕터 데이터가 사라질 위험이 있다. **운영 DB로 직접 재현하지는
않았다**(SDK 소스 확인까지만). 이 티켓에서 트랜잭션으로 `parts` 전체를 다시 쓰는 방식으로 교체했다.

## 남은 작업
- 질문 수가 많아 300초를 넘기면 서버가 끊긴다. 그 경우 "이어서 생성"으로 복구되지만, 자주 그렇다면 단계를
  나눠 서버가 다음 단계를 스스로 다시 호출하는 구조가 필요(배포 보호 설정과 충돌할 수 있어 지금은 채택하지 않음)
- 스타일 참고 이미지 영구 저장(AM-04)이 끝나면 요청에 이미지를 싣지 않아도 됨
