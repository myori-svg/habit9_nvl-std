# [SA-05] 캐릭터 이미지 저장소를 Vercel Blob으로 교체

## 상태
진행 중 (구현·저장소 단위 검증 완료, 실사용 확인 대기)

## 카테고리
저장·아카이브

## 배경
Firebase Storage는 무료(Spark) 요금제에서 접근이 막혀 있어(공식 정책: 402/403), 캐릭터 이미지가
한 번도 영구 저장되지 않았음. 프로덕션 DB의 캐릭터 101명 중 이미지 주소가 있는 캐릭터는 0명이고
`imageGenerated` 표시만 34명에 남아 있었음. 그 결과 새로고침 후 자동 모드 장면 생성에서 캐릭터 참고
이미지가 빠졌음.

## 결정
- 캐릭터 이미지만 영구 저장. 장면 이미지는 저장하지 않고 화면 표시·다운로드만 (백업 중요도 낮음)
- 저장소는 Vercel Blob **비공개(private)** 보관함. 무료 한도(Hobby): 저장 1GB / 전송 10GB. 한도 초과 시
  과금 없이 30일간 접근 제한
- 이미지는 WebP로 받아 저장 (같은 화질에서 PNG보다 훨씬 작음)

## 구현
- `app/api/blob-upload/route.ts`: 브라우저 직접 업로드용 짧은 유효기간 허가증 발급. 캐릭터 이미지 경로
  (`novels/<novelId>/characters/<charId>.<ext>`)·WebP/PNG/JPEG·10MB만 허용, 같은 경로는 덮어씀
- `lib/blob-upload.ts`: 브라우저에서 Blob으로 직접 업로드 (요청 크기 4.5MB 한도 회피)
- `lib/image-url.ts`: 서버가 저장된 주소에서 경로만 뽑아 비공개 보관함에서 읽음 (경로 규칙 검사로 임의
  주소 차단)
- `app/api/generate-scene`: 캐릭터 이미지를 주소(`imageUrl`)로 받아 서버가 직접 읽음 (없으면 base64)
- `lib/firestore.ts`: `saveCharacterImage`를 Blob 업로드로 교체, 캐릭터 문서 갱신 시 in-memory 전용
  필드(`imageBase64`/`imageMime`) 제거. 장면 이미지 저장 함수·Firebase Storage 초기화 제거
- `lib/store.ts`: 저장이 실패해도 그 세션에서는 캐릭터 이미지를 참고 이미지로 쓰도록 in-memory 선반영
- `components/WorkPanel.tsx`: 장면 이미지는 이번 세션 화면에만 유지 + 다운로드
- `components/ManualPanel/CharImageStep.tsx`: "생성됨" 표시를 실제 이미지(주소 또는 세션 이미지) 기준으로 변경
- `lib/openai-image.ts`: 출력 형식을 WebP(압축 85)로 지정

## 남은 작업
- 스타일 참고 이미지도 메모리 전용(새로고침 시 소실, 서버로 통째로 전송) — 필요 시 같은 방식으로 저장
- 자동 모드 장면 프롬프트가 코드에 고정돼 있어 설정의 장면 양식을 쓰지 않음
- OpenAI 실패 시 Gemini로 이미지 생성을 대체하는 fallback
- Vercel 환경변수 `BLOB_READ_WRITE_TOKEN`, `BLOB_STORE_ID` (보관함 연결 시 자동 추가), 병합 후 재배포
