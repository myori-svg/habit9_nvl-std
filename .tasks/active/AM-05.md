# [AM-05] 자동 모드 장면 이미지 백그라운드 생성 + 영구 저장

## 상태
진행 중 (구현 완료, 실사용 확인 대기)

## 카테고리
Auto Mode

## 배경
자동 모드는 화면(브라우저 탭)이 켜져 있는 동안 자바스크립트가 한 장씩 순서대로 그림을 요청·대기하는
구조였고, 완성된 그림도 그 탭의 메모리에만 있다가 새로고침하면 사라졌다(SA-05 결정: "장면 이미지는
저장하지 않음"). 모바일에서 앱을 이탈했다가 돌아오면 브라우저가 그 탭을 통째로 버렸다가 새로고침하는
경우가 있어, 진행 중이던 생성과 이미 만든 그림이 통째로 날아갈 수 있었다.

## 결정
- 그림 1장당 요청 1개는 유지하되, 실제 생성은 Next.js `after()`로 응답 이후로 미뤄서 화면이 요청을
  붙들고 기다리지 않게 함. Vercel 함수 실행 시간 제한을 신경 쓸 필요가 없어짐(요청 자체는 즉시 끝남).
- 저장 경로는 질문의 임의 ID가 아니라 "파트 + 질문 순번 + 슬롯"이라는 고정 자리로 잡아, "전체 다시
  생성"으로 질문 ID가 바뀌어도 항상 같은 자리를 덮어써서 저장 용량이 늘어나지 않게 함.
- 보관함이 비공개 전용이라(공개 저장 시도 시 "private store" 오류 확인) 장면 이미지도 **비공개**로 저장하고,
  화면에는 서버 경유 주소(`/api/scene-image`)로 보여줌. 같은 경로를 덮어써도 옛 그림이 캐시되지 않도록
  주소에 생성 시각(`v`)을 붙임.
- 정리 배치는 **고아 파일만**(챕터/질문이 삭제되거나 개수가 줄어 더 이상 어떤 슬롯도 가리키지 않는
  파일) 대상으로 하고, 방금 생긴 고아를 보호하기 위해 2달 유예를 둠. 지금 화면에 실제로 쓰이고 있는
  최신 그림은 아무리 오래돼도 지우지 않음. 실행 주기는 한 달에 1회(Vercel Cron, Hobby 플랜도 하루 1회
  까지는 지원해서 문제 없음).

## 구현
- `app/api/generate-scene/route.ts`: `novelId`/`partId`/`dqId`/`dqIndex`/`slot`을 받아 검증 후
  `after()`로 실제 생성을 미루고 `{ accepted: true }`를 즉시 반환. 실패 시 Firestore에 에러 메시지 기록.
- `lib/scene-generation.ts` 신설: 프롬프트 조립(`buildScenePrompt`)·캐릭터 참조 이미지 해석
  (`resolveSceneReferenceImages`)을 라우트에서 분리.
- `lib/scene-image-storage.ts` 신설: 고정 경로 계산(`sceneImagePath`)과 서버 직접 업로드
  (`uploadSceneImageToBlob`, `access: 'private'`, `allowOverwrite: true`) + 화면용 주소 생성.
- `app/api/scene-image/route.ts` 신설: 장면 이미지 경로 규칙에 맞는 경로만 비공개 보관함에서 읽어 내려줌.
- `lib/firestore.ts`: `saveSceneImage`/`saveSceneImageError` 추가 — 최신 문서를 다시 읽어 `partId`/`dqId`
  로 현재 배열 위치를 찾은 뒤 `updateDoc`으로 해당 슬롯 필드만 갱신(다른 필드와 충돌 없음).
  `stripSceneImages`가 `url`과 함께 `error`도 보존하도록 수정.
- `types/index.ts`: `SceneImage`에 `error?: string` 추가.
- `components/WorkPanel.tsx`: 요청 후 base64를 기다리지 않고 바로 끝남. `itemStatus`는 Firestore 실시간
  구독(`lib/store.ts`의 `startSync`)을 통해 들어온 `novel` prop 변화를 감지하는 `useEffect`로 완료/실패
  전환. 세션 전용 `sessionImages`·`addHistory` 제거(Auto Mode 결과는 이제 Archive 탭이 아니라 DQ 카드
  자체가 영구 보관소). 다운로드는 base64 데이터 URI 대신 Blob 공개 주소를 새 탭으로 여는 방식으로 변경.
- `app/api/cleanup-scene-images/route.ts` 신설: `CRON_SECRET` 인증 후, 모든 novel이 실제로 참조 중인
  장면 이미지 경로 집합을 만들고 `/scenes/` 하위 중 그 집합에 없으면서 2달 넘은 것만 삭제.
- `vercel.json` 신설: 매달 1일 새벽(UTC) 위 라우트 호출하는 cron 등록.
