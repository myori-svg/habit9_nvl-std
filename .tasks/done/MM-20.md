# [MM-20] DQ 프롬프트 챕터 선택이 반영 안 되는 버그 수정

## 상태
완료

## 우선순위
🔴 긴급 (사용자가 직접 발견해서 요청)

## 카테고리
Manual Mode

## 증상
① DQ 생성 단계에서 챕터를 선택해도 "Gemini에 붙여넣을 프롬프트" 박스에
해당 챕터 내용이 조립되지 않고, 매번 "(챕터를 선택하거나 직접
입력해주세요)"라는 placeholder 문구만 보임.

## 원인
`PromptBox`의 "템플릿으로 저장" 기능(`reverseTemplate`)이, 저장 시점에
`vars`의 어떤 값이 비어 있으면(`if (!value) return text`) 그 자리를 다시
`{{변수}}`로 되돌리지 못하고 그냥 넘어감. 그런데 화면에 보이는 텍스트
자체는 `buildDQPrompt`가 빈 값 대신 넣어준 안내문구("(챕터를
선택하거나...)")가 이미 박혀 있는 상태라, 그 안내문구가 그대로 "템플릿"에
문자 그대로 저장돼버림 — 즉 `{{selectedSummary}}` 자리가 통째로 고정
문자열로 굳어버려서, 그 뒤로는 어떤 챕터를 골라도 반영이 안 됨.

실제로 프로덕션 Firestore에 저장된 BGF 소설의 커스텀 DQ 템플릿이 정확히
이 상태였음 (아마 챕터 선택 전에 프롬프트를 커스터마이징하고 저장 버튼을
누른 것으로 추정) — 라이브로 재현 후 직접 확인.

## 조치
1. **데이터 복구**: 이미 망가진 상태로 저장되어 있던 실제
   `promptTemplates.dq` 커스텀 템플릿을, 사용자가 써둔 커스텀 지침은
   그대로 보존한 채 "(챕터를 선택하거나...)" 부분만 다시
   `{{selectedSummary}}`로 되돌려서 재저장 (기존 프로덕션 데이터 직접
   수정 — 코드 배포와 무관하게 즉시 적용됨)
2. **재발 방지**: `vars`에 비어 있는 값이 하나라도 있으면 "템플릿으로
   저장" 버튼을 아예 비활성화하도록 `PromptBox`(shared.tsx) 수정. 같은
   구조를 쓰는 다른 단계(②구도의 `characterNote`, ④장면의
   `styleImageNote`)도 동일한 위험이 있어서 같이 방어됨. 이미 각자
   내부적으로 fallback 문자열을 `vars`에 직접 넣어두는 방식(③ 캐릭터
   프롬프트/이미지)은 원래도 안전해서 영향 없음.

## 확인
- Playwright로 실제 재현 → 수정 → 챕터 선택 시 실제 내용이 프롬프트에
  들어가는 것 확인
- 챕터 미선택 상태에서 "템플릿으로 저장" 버튼이 비활성화되는 것 확인
- 챕터 선택하면 다시 활성화되는 것 확인
