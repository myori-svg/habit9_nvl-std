# [AI-01] Gemini SDK 마이그레이션 (@google/generative-ai → @google/genai)

## 상태
완료

## 우선순위
🔴 긴급 (전체 Gemini 호출 장애)

## 카테고리
AI 연동

## 목표
"Gemini API 콜이 자꾸 에러난다"는 증상의 원인 파악 및 수정.

## 원인
`@google/generative-ai`(구 SDK)는 2025-11-30부로 지원이 완전히 종료됨
(https://github.com/google-gemini/deprecated-generative-ai-js). 오늘
기준 9개월 이상 지난 상태 — 이 저장소는 계속 이 구 SDK(`^0.24.0`)를 쓰고
있었음. `generate-scene`/`generate-character-image`/`setup-novel`의
이미지 생성 호출은 `responseModalities`/`imageConfig`가 구 SDK 타입에
아예 없어서 `as never` / `@ts-expect-error`로 억지로 우회하고 있었던 것도
같은 원인의 방증.

## 수정 내용
- `@google/generative-ai` 제거, `@google/genai`(공식 후속 SDK, 최신
  `googleapis/js-genai`) 설치
- `lib/gemini.ts`: `GoogleGenerativeAI` → `GoogleGenAI` 통합 클라이언트로.
  `genAI.getGenerativeModel(...).generateContent(...)` 패턴 →
  `ai.models.generateContent({model, contents, config})` 패턴으로 전환
- `generateContentWithRetry`가 이제 `(ai, params)`를 받도록 시그니처 변경
  (기존엔 `(model, request)`)
- PROHIBITED_CONTENT 재시도 로직: 새 SDK는 `BlockedReason`/`FinishReason`
  enum에 `PROHIBITED_CONTENT`가 정식으로 타입에 포함되어 있어 기존의
  string 캐스팅 우회가 필요 없어짐. 이미지 전용 차단 사유인
  `IMAGE_PROHIBITED_CONTENT`도 함께 체크하도록 보강
- `response.text()` (함수 호출, 차단 시 예외 던짐) → `response.text`
  (프로퍼티, 차단 시 `undefined`)로 SDK 쪽 동작이 바뀌어서, 이 차이를
  흡수하는 `requireText()` 헬퍼를 추가하고 텍스트를 꺼내는 9곳 전부 교체
  (안 그러면 차단 시 에러 메시지 없이 `undefined.trim()`으로 죽음)
- 영향받은 라우트 전부 수정: `generate-dq`, `generate-character-info`,
  `generate-character-prompt`, `generate-character-image`,
  `generate-scene`, `setup-novel`
- 이미지 생성 설정(`responseModalities`, `imageConfig.aspectRatio`)이
  새 SDK 타입에 정식으로 있어서 `as never`/`@ts-expect-error` 우회 전부
  제거됨
