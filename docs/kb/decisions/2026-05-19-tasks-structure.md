# [Decision] 태스크 관리 구조 및 클코 워크플로우 설계

## 날짜
2026-05-19

## 배경
기존에 Notion 프로젝트 트래커와 `docs/checklist.md` 두 곳에 분산되어 있던 태스크 관리를
Claude Code가 읽고 작업할 수 있는 구조로 일원화하기로 결정.

네이버 개발자 특강 ("딸깍보다 중요한 설계자") 내용을 참고하여
Rules + Skills + KB 구조를 nvl-std에 맞게 적용.

## 결정 사항

### 1. 태스크 관리 일원화
- **결정**: Notion 트래커 → `.tasks/` md 파일로 이전, `checklist.md` 흡수
- **이유**: Claude Code가 직접 읽고 작업할 수 있어야 함. 두 곳 유지 시 한쪽이 필연적으로 썩음
- **구조**:
  ```
  .tasks/
  ├── README.md     # 전체 현황 인덱스 (클코가 제일 먼저 읽는 것)
  ├── active/       # 긴급 / 진행 중
  ├── backlog/      # 나중에
  ├── hold/         # 보류
  └── done/         # 완료
  ```

### 2. 티켓 단위 정의
- **결정**: "Claude Code가 한 번에 작업 시작하고 PR 하나로 끝낼 수 있는 단위"
- **이유**: 너무 크면 중간에 막힐 때 전체 블로킹, 너무 작으면 컨텍스트 스위칭 비용
- **예시**: SA-02(함수) + SA-03(UI)는 합쳤지만, 이미지 업로드 관련 CH-08/MM-07은 SA-02에 의존성만 걸고 분리

### 3. 의존성 포맷
- **결정**: `depends_on` / `blocks` / `recommends` 세 가지로 명시
- **이유**: "선행 권장", "없음" 같은 애매한 표현은 클코가 판단하기 어려움
- **규칙**:
  - `depends_on`: 이 티켓 완료 전엔 시작 불가 (하드 블로킹)
  - `blocks`: 이게 완료돼야 해당 티켓 시작 가능 (역방향 명시)
  - `recommends`: 먼저 하면 좋지만 블로킹은 아님

### 4. 의존성 체크 시점
- **결정**: 티켓 시작할 때 `depends_on` 확인 (1번 방식)
- **이유**: 완료 시마다 전체 순환 업데이트(2번)는 파일 관리 복잡도가 높음. `done/` 폴더 존재 여부로 체크하면 단순하게 해결
- **규칙**: CLAUDE.md에 명시 — depends_on 티켓이 done/에 없으면 그것부터 작업

### 5. CLAUDE.md 역할 (Rules)
- **결정**: 레포 루트에 두고 클코가 세션 시작 시 제일 먼저 읽는 파일로 사용
- **포함 내용**: 프로젝트 개요, 기술 스택, 디렉토리 구조, 작업 규칙, 주의사항

### 6. docs/kb/ 구조 (Knowledge Base)
- **결정**: 기능 단위 티켓(.tasks/)과 별도로 결정 맥락을 KB로 관리
- **이유**: 티켓은 "무엇을 할지"만 담고, "왜 이렇게 됐는지"는 KB에
- **구조**:
  ```
  docs/kb/
  ├── decisions/    # 설계 결정 로그 (이 파일)
  ├── architecture/ # 아키텍처 설명
  └── context/      # 배경 (학원, 선생님 사용 등)
  ```
